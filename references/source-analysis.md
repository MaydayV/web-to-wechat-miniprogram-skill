## `launch-wechat-miniprogram`

**有价值的地方**

- 给出从需求、设计、环境、开发到发布的生命周期框架，适合防止只移植静态画面而漏掉真实闭环。
- 强调已有项目盘点、原生 WXML/WXSS 映射、微信导航/安全区、API/云端写入校验和多层验证。
- 对风险能力和证据等级有明确边界，避免把编译、模拟器和真机结果混为一谈。

**局限和取舍**

- 面向完全新手从构想到上线，篇幅长、阶段确认门禁多；不适合每个已有 URL 迁移都完整走一遍账号注册、三套 UI 方案和发布流程。
- 以新产品发现为主，没有把路由爬查、网页控件/状态抽取、浏览器 API 差异和 URL-only 信息边界组织成直接迁移流程。
- 本 Skill 保留阶段意识、现有项目盘点和分层验收；只在未知会改变范围/数据/权限时提问，不把新项目的强确认门禁套在清晰的迁移任务上。

## `miniprogram-skills`

**有价值的地方**

- 每个 Skill 目标窄、能按问题加载；官方脚手架核对、CLI 编译、GUI 运行证据、环境阻塞分类和安全恢复都有具体流程。
- 清楚区分静态/CLI 证据与真实页面点击，强调检查报告和 trace，而非凭截图或命令启动就宣称通过。
- 对自动修复边界和宿主工具依赖保持诚实，避免在工具链问题上盲目改代码。
- `miniapp-center-hub-refactor` 和 `miniapp-user-facing-copy-trim` 提供了多入口按任务归组、保留复杂子流程，以及把冗长说明改成短而行动导向的用户文案方法。
- DevTools recovery 适合定位错根目录、模板残留等工具污染；只在出现这些迹象时进入，不把它变成每次转换都要跑的清理步骤。

**局限和取舍**

- 仓库是微信小程序开发的多个专用 Skill 集合，不是一个网站到小程序的端到端迁移 Skill；没有提供 URL 页面抽取和样式/功能/API 映射。
- 当前 README 标注暂停主动维护；仓库提到的工具与平台行为仍应在实际环境确认。本 Skill 仅吸收流程模式，不依赖其 GUI harness 或固定工具版本。
- 本 Skill 保留“CLI 先验证编译、GUI 仅补运行证据、按证据分层”的方法，但不复制所有专用 Skill、脚本、测试夹具或工具依赖。
- Hub 重组、文案精简和 DevTools 恢复按实际需要触发；它们不会强制改变小型网站的导航，也不会覆盖用户现有品牌或项目结构。

## `raidenfc/my-skills`

**有价值的地方**

- `html-to-miniprogram` 强调多路由页面不能只靠目录列表：要交叉搜索路由注册、导航链接、事件跳转和条件渲染视图，减少漏页。
- 它还给出 HTML/React/Vue 标签、事件、列表和路由到 WXML/原生导航的具体映射，以及页面文件集合和逐项对照验证；这些映射已放入迁移工作流，并明确只迁移功能语义，不搬源站样式。
- 转换蓝图把页面、路由、样式、图标、交互和验证收在一处，适合多页面迁移时作为执行清单与事实来源。
- `static-to-api-layer` 从列表/详情/筛选/分页/表单/状态变更/聚合统计等行为识别潜在数据接口，有助于避免把数据型页面误当成纯静态 UI。
- 将页面 API 调用与请求基础层分离，以及把“发现接口”与“生成正式 API 契约/文档”区分职责，有利于迁移渐进落地。

**局限和取舍**

- `html-to-miniprogram` 明确把业务逻辑、网络、认证和持久化排除在转换范围外，并将此类动作替换为 Mock/Toast；这与用户要求迁移网站功能逻辑不完全匹配。此 Skill 只允许在明确演示态使用集中 Mock，真实业务交互必须接已确认 API，否则标记为待接入。
- 该 Skill 要求固定设计决策确认模板、逐项确认并初始化固定 `miniprogram/` 骨架；我们只保留会影响范围/架构的确认，并尊重目标仓库现有小程序根目录。
- `static-to-api-layer` 的接口分类适合作为发现线索，但自动推断 endpoint 和默认 `IS_MOCK=true` 可能掩盖契约缺失或产生假成功。本 Skill 将候选 API 标为待确认，依据真实源码/契约实现，不在生产流程以 Mock 代替后端。
- 原仓库未在克隆内容中提供顶层许可证文件；本 Skill 只吸收方法和概念，没有复制其源码、脚本或模板。原仓库 README 列出的 CSS 与平台支持断言不作为规范事实，具体兼容性仍须按目标基础库和官方资料验证。

## 合并后的设计

以 URL/Web 仓库为产品研究来源，使用 `launch-wechat-miniprogram` 的阶段、项目状态与验收方法，加上 `miniprogram-skills` 的脚手架核对、CLI/GUI 故障分类、按需页面 hub 与文案精简，再吸收 `my-skills` 的 HTML/事件映射、页面交叉盘点、迁移蓝图、API 需求发现、请求层分离和可选契约校验。先用静态证据梳理网站，再对动态缺口做最少浏览器补查；提炼选题和高层功能，明确原创产品概念与改进点，视觉、文案、内容和资源独立创作。保留 URL-only 的权限边界与真实后端契约，不复制源 Skill、脚本、测试夹具或未经核验的平台断言。\n
